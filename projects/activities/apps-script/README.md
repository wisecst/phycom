# 교사 전용 Sheets 연결 설정

아직 Google 계정 연결·API 배포는 실행하지 않았습니다. 기존 로컬 조편성은 연결 없이 그대로 사용합니다.
교사 연결 후에만 Google 서버로 학생 명단을 보냅니다. 실제 학생 정보·토큰을 GitHub에 올리지 마세요.

## Google 관리자/교사가 설정할 내용

1. **하나의 독립 Apps Script 프로젝트**를 만듭니다. `Code.gs`를 복사하고, 상위 경로의
   `sheets-model.js` 내용을 `Model.gs`로 복사합니다. `appsscript.json`도 적용합니다.
   모델 파일은 브라우저/서버가 같은 역할 검증을 사용하기 위한 공통 원본입니다.
2. Apps Script를 표준 Google Cloud 프로젝트에 연결합니다. 같은 Cloud 프로젝트에서
   **Apps Script API**와 **Google Sheets API**를 사용 설정합니다. Advanced Sheets 서비스는 manifest에 포함돼 있습니다.
3. 스크립트 속성에 다음을 설정합니다. 파일 ID는 브라우저나 공개 소스에 저장하지 않습니다.
   - 기존 학년도 파일이 있다면 확인한 ID를 `SPREADSHEET_2026`에 `{"id":"실제 ID","state":"ready"}`로 연결합니다.
     파일명으로 추정하거나 같은 자료를 새 Apps Script 프로젝트에 중복 연결하지 않습니다.
   - `CREATE_YEARS`: 기존 파일이 없음을 관리자가 확인한 학년도의 JSON 배열(예: `[2026]`).
     이 승인이 없는 학년도는 자동 생성하지 않습니다. 승인 후 최초 저장에서만 파일을 생성합니다.
   - `TEACHER_EMAILS`: 허용할 실제 교사 이메일의 소문자 JSON 배열. 기본은 빈 목록(모두 거부).
   - `SCHOOL_YEARS`: 현재 `data.js`의 `schoolYears`와 동일한 JSON 객체. 현재 `{"2026":13}`.
     웹교재가 보내는 학급 수와 서버 설정이 다르면 요청을 거부합니다. 클라이언트가 임의 학급을 생성할 수 없습니다.
4. **API 실행 파일(API executable)**로 버전을 배포합니다. **웹 앱으로 공개 배포하지 않습니다.**
   기본 manifest의 `MYSELF`는 소유 교사만 실행할 수 있습니다. 여러 교사가 사용하려면
   조직 정책에 맞는 실행 API 접근 범위를 설정하고, `TEACHER_EMAILS`로 모든 호출자를 재검증합니다.
   첫 교사가 만든 학년도 스프레드시트는 다른 허용 교사에게 직접 편집 권한을 공유해야 합니다.
   파일 권한이 없는 경우 기존 ID로 열기 오류가 나며 대체 파일을 생성하지 않습니다.
5. 같은 Cloud 프로젝트에 **웹 애플리케이션 OAuth 클라이언트**를 만듭니다.
   실제 사용하는 출처(예: `https://wisecst.github.io`)를 승인된 JavaScript 원본에 등록합니다.
   동의 화면의 Sheets 및 이메일 권한을 설정합니다. 테스트 모드라면 교사를 테스트 사용자에 등록하고,
   조직 외 배포라면 Google의 민감 범위 검증/앱 게시 요건을 충족해야 합니다.
   OAuth 클라이언트 보안 비밀번호는 사용하거나 웹페이지에 넣지 않습니다.
6. 웹교재 8/9페이지의 **Google 연결**에서 OAuth 클라이언트 ID와 **스크립트 ID**를 입력합니다.
   `/macros/s/.../exec` 주소나 배포 ID가 아닙니다. 설정값만 브라우저 localStorage에 보관합니다.
   액세스 토큰은 메모리에만 보관하고, 만료 시 자동 우회 없이 다시 로그인을 요구합니다.

## 접근 방식/브라우저 제약

- GIS(`accounts.google.com/gsi/client`)의 OAuth 토큰 팝업 → HTTPS
  `script.googleapis.com/v1/scripts/{SCRIPT_ID}:run`을 사용합니다.
- 실행 API가 Bearer 토큰을 검증하고, 서버 함수가 `Session.getActiveUser().getEmail()`을
  허용 목록과 비교합니다. 이메일을 클라이언트 요청에 넣어 인증하지 않습니다.
- 서버의 이메일 식별이 비어 있거나 권한/팝업/쿠키/네트워크/조직 정책 때문에 실패하면 중단합니다.
  CORS 프록시, JSONP, URL 토큰, 익명 `doGet`/`doPost`, 공개 공유 스프레드시트로 우회하지 않습니다.
- 토큰·학생 정보는 URL/로그/공개 저장소에 기록하지 않습니다.
- 연결 해제는 이 페이지의 토큰만 폐기합니다. Google 계정의 앱 권한 철회는 Google 계정 설정에서 수행합니다.
  기존 세션 데이터는 사용자 요청대로 삭제하지 않습니다. 공용 PC에서는 브라우저 탭을 닫으세요.

## 저장 및 이전

- 기존 sessionStorage 키와 명단 입력은 보존됩니다. 연결할 때 Sheets와 다르면 덮어쓰기 전에 확인합니다.
  **현재 결과 저장**으로 기존 로컬 조편성을 이전할 수 있습니다. **다시 불러오기**로 교사의 시트 수정을 반영합니다.
- 연결된 상태에서 자동 조편성하면 같은 학급으로 저장을 시도합니다. 실패 시 로컬 결과를 유지하고 실패 상태를 표시합니다.
- 모둠 구성과 프로젝트 연결 정보가 충돌하면 해당 조별로 확인합니다. 프로젝트 정보가 있는 모둠을
  없애는 재편성은 저장을 거부하므로 먼저 교사가 해당 연결 정보를 정리해야 합니다.
- Sheets가 기준입니다. 다른 교사/직접 편집으로 버전이 달라지면 다시 읽고 확인해야 하며 자동 덮어쓰지 않습니다.
- 역할 변경은 9페이지의 모둠 번호를 눌러 엽니다. 같은 학생 명단 안에서만 역할을 재배정하며,
  3인은 프로듀서가 엔지니어를 겸임, 4인은 역할별 1명, 5인은 한 역할만 2명입니다.
- 시트 A:J가 공개된 항목표이고 L:M은 마지막 저장 요청 ID/해시입니다. L:M을 수정하지 마세요.
  직접 수정할 때 같은 모둠의 주제·개요·슬라이드 정보는 모든 학생 행에서 일치시킵니다.
  학생 중복, 모둠 인원/역할 오류, 서로 다른 메타데이터는 로드 오류로 표시합니다.
- 슬라이드 ID/URL만 저장합니다. Google 슬라이드 자동 생성/내용 추출은 구현하지 않습니다.

## 중복·장애 복구

- 전역 ScriptLock, 스크립트 속성 `SPREADSHEET_학년도`의 영구 ID, 요청 ID, 내용 해시를 사용합니다.
  스프레드시트 파일명으로 식별하지 않습니다. 재배포도 **동일한 Apps Script 프로젝트**를 사용합니다.
- 첫 파일 생성 전에 `creating` 표식을 저장하고, 생성 직후 ID를 기록합니다. 중단 표식이나 파일 접근 오류는
  자동 대체 생성으로 처리하지 않습니다. 관리자에게 오류를 보여주고 멈춥니다.
- `creating`에 멈췄으면 관리자가 Drive에서 실제 생성 여부를 확인하여 **유일한 실제 파일 ID**를 확보해야 합니다.
  `initializing`이면 해당 파일의 1반~13반 및 A:J 항목을 확인합니다. 관리자 확인 후에만 해당 속성을
  `{"id":"확인한 실제 ID","state":"ready"}`로 복구합니다. 기록을 지우고 재시도하면 중복 위험이 있습니다.
- 저장은 단일 Sheets `batchUpdate`로 해당 학급의 값과 요청 기록을 함께 갱신합니다.
  요청 실패 시 부분 삭제가 일어나지 않으며, 네트워크 응답 유실은 재조회/동일 요청의 결과 확인으로 처리합니다.
- ScriptLock은 이 앱의 동시 요청을 직렬화합니다. Sheets 직접 편집은 Apps Script 잠금을 따르지 않습니다.
  **Google Sheets API에는 수동 UI 편집까지 포함한 원자적 버전 조건 쓰기가 없습니다.**
  버전 검사는 요청 사이의 변경을 탐지하지만 조회와 쓰기의 매우 짧은 사이에 발생하는 수동 편집까지
  완전히 배제하지는 못합니다. 저장 중에는 시트를 직접 편집하지 않고, 필요시 Sheets 버전 기록으로 복원합니다.
  이 제한을 숨기거나 실제 동시 수동 편집 무손실을 검증 완료로 표시하지 않습니다.

## 배포 전 실제 확인

교사 OAuth 인증/비허용 계정 거부, 2026 파일 한 개와 13개 탭, 24~32명 저장/재조회,
다른 브라우저·기기 복원, 3/4/5인 역할 수정, 시트 직접 수정 후 새로 읽기, 네트워크 끊김과
동시 교사 저장 충돌을 실제 계정으로 확인해야 합니다. 현재 자동 검증은 모형 서버/브라우저 테스트이며
Google 실계정 배포 검증을 대신하지 않습니다.

## 로컬 검증 명령

프로젝트 활동 폴더에서 `node tests/sheets.test.cjs`를 실행합니다.
Playwright와 Chromium이 있는 환경에서는 `python tests/google-flow.py`로 브라우저 흐름도 확인합니다.
후자는 OAuth/Sheets 응답을 테스트용으로 모형화하며 실제 Google 연결 검증이 아닙니다.
